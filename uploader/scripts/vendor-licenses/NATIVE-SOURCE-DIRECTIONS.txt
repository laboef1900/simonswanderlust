Native libraries and runtime-base source directions
Reviewed 2026-10-27. These directions cover the exact versions named below, not
uninspected historical images or a future build that resolves different inputs.
The application imposes no restriction on modifying/replacing LGPL-covered
libraries or reverse engineering for debugging those modifications.

Each pinned build repository contains build.sh, platform toolchains,
versions.properties and build/posix.sh. The latter identifies source archives,
external patches and inline modifications. third-party-image-evidence.json lists
those URLs, review-time hashes, library notices and original librsvg Cargo.lock
crate archives/checksums. The original lock is a conservative dependency superset:
Cargo --workspace preserves existing non-workspace versions when the script
removes image/Cairo features. It is not a per-binary linkage inventory.
https://doc.rust-lang.org/cargo/commands/cargo-update.html

To replace the library, use the matching pinned build inputs for the image's
architecture/libc, rebuild a compatible libvips-cpp shared library, and put it in
the matching @img/sharp-libvips-linux-{arm64,x64}/lib package directory in BOTH
/app/uploader/node_modules and /app/site/node_modules of a derived image.
Preserve the expected SONAME/ABI and accompanying notices. The upstream scripts
contain the actual link options, including statically incorporated dependencies;
a generic unmodified libvips source download is not a substitute for those inputs.
No rebuild/relink run is claimed here. Review-time hashes do not establish which
bytes a mutable upstream PR patch URL returned when an older binary was built.

The source manifests were reachable. Docker's documented source-artifact and

For example, use Docker Scout attest get on the exact runtime digest with
--predicate-type https://docker.com/dhi/source/v0.1 --verify --platform linux/arm64
(or linux/amd64), then retrieve the attested source-image digest with the Docker
registry tooling described there. The verified SBOM components, source digests
and verification method are retained in third-party-image-evidence.json.
Base component copyright files/common license texts remain in the image's
/usr/share/doc and /usr/share/common-licenses. Node's complete 26.12.1 LICENSE is
also included in these supplemental notices; source is available at
https://github.com/nodejs/node/tree/v26.12.1

None of this changes old image bytes or certifies legal compliance. Before an
additional distribution, confirm actual resolved versions/source accessibility,
notice delivery and applicable source/relink obligations for that artifact.
