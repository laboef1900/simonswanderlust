# GitHub automation hardening

Status: owner-approved release contract, 2026-11-13. Risk: high (release pipeline); remaining changes are normal-risk test/automation changes.

## Approval and scope

The owner approved stable version tags pointing at the current main revision with successful CI; each native architecture is built once, and those exact candidate images must pass packaged ownership/restore qualification and legal asset checks before version/latest tags are promoted. Failed qualification must publish no release tags. Deployment-mount qualification remains a separate operational gate. No release, deployment, push, or PR is authorized by this implementation request.

The owner separately approved changing the repository default workflow token permissions to read-only and disabling the obsolete issue-292/issue-304 workflow registrations while preserving their history.

On 2026-11-14, the owner explicitly superseded that history-retention decision:
delete all 11 historical runs of those two retired workflows, including their logs
and artifacts. This permanently removes qualification evidence; the owner accepted
that loss. Scope is limited to issue-292/issue-304; current CI, release, security,
coverage and dependency automation remain unchanged. This is a one-time cleanup
authorization, not a continuing retention-policy change.

## Invariants and trust boundaries

- PR CI has read-only repository access, no persisted checkout credential, no registry credentials, bounded jobs, and cancels superseded PR runs only.
- Release eligibility rejects malformed/prerelease tags, revisions not at the current protected main tip, and missing/failed CI. A bounded wait may accommodate the main-push CI race.
- Release credentials are available only after eligibility succeeds. Native amd64/arm64 candidate builds must match the source SHA; promotion rechecks eligibility. Candidate staging references may exist before promotion, but stable/version/latest references and GitHub Releases must not.
- Qualification exercises the actual candidate image on native runners, both named-volume and bind-mount modes. Checks do not qualify a deployment filesystem. Promotion reuses qualified image digests rather than rebuilding.
- Legal source provenance and assets are checked on each candidate. No dumps, credentials, private fixtures, or raw application logs are uploaded.
- Built-output regression fixtures use disposable PostgreSQL databases/schemas, private output/cache directories, all four language modes, real Astro builds, published and unpublished content. Existing public routes are not changed. Historical byte-parity qualification is distinguished from continuously maintained semantic contracts; fixtures must never be generated by copying the output under test into an expected baseline.
- Browser smoke tests use disposable local app/data/database fixtures, exercise real browser interactions and public output, and never contact production or real AI providers. Existing auth/publish/slug rules remain unchanged.
- Accessibility checks resolve actual labels/names, including absent, empty, and dangling references. Behavioral tests replace brittle source spelling or decorative-class checks without dropping their meaningful contracts.
- Dependency/security automation has least privilege; updates include regenerated legal inventory. No security test, type check, or compliance gate is disabled.

## Acceptance and verification

Keep required check names stable. Add executable populated-build contracts, a small browser smoke lane, action/workflow validation, and targeted regression coverage for release eligibility and the accessible-name false negative. Run both affected Vitest suites, uploader typecheck, Astro check, browser smoke, and workflow validation once after integration. Inspect actual CI history to target runtime improvements; shared-database suites remain serialized unless isolated. Report native Linux/DHI and remote CI checks that cannot be executed locally rather than claiming qualification.

## Recovery and containment

Changes remain on a feature branch until reviewed and green CI. A failed candidate is never promoted; the deployed image and existing release tags remain untouched. Roll back automation through a reviewed revert, not by bypassing eligibility or qualification. Restore the prior GitHub default permission or re-enable historical workflow registrations only with owner authorization. Disposable fixture cleanup is restricted to resources created by the current verification run. User work and persistent application data are out of scope.

Registry tag updates are not atomic across version/minor/latest. A transport failure during
promotion may leave a subset pointing at the already-qualified digest. Inspect the recorded
digest and rerun failed jobs from the same run; do not rebuild a different image under an
existing version. Promotion refuses to overwrite an existing version with another digest.
A failed qualification, unlike a failed promotion transport, touches no release tags.
If main has moved, keep promotion stopped and resolve through reviewed roll-forward; never
move main or replace a published tag to bypass eligibility.

## Operating the checks

Install both trees (`npm ci --prefix site`, `npm ci --prefix uploader`), build the native
addon (`npm run build:native --prefix uploader`) and supply `TEST_DATABASE_URL` pointing
only at a disposable PostgreSQL 18 service. Browser fixtures create/drop their own database;
populated build fixtures create/drop only their own schemas and private output directories.
Managed SQL recovery tests also require PostgreSQL 18 `pg_dump` and `psql` on `PATH`.

- `cd site && npm run test:built-contracts`: 24 real builds across four modes; route inventories,
  disabled/draft privacy, pages/navigation, journeys and packaged legal-link targets. Identity
  uses the actual stored-identity-to-build-snapshot boundary. Before/live/dormant are distinct
  database states on current code, not fabricated historical reference builds.
- `cd uploader && npx playwright install chromium && npm run test:e2e`: actual app, PostgreSQL,
  browser and publication. Login, save/reload, expired-session recovery, modal keyboard/focus,
  public output and initialized visible form names. No production content, AI calls or
  credential-bearing traces; screenshots remain local, not workflow artifacts.
- `node --test .github/release/*.test.mjs`: release eligibility and digest-boundary refusals.
  CI also runs the digest-pinned actionlint image, including shell checks.
- Weekly/manual `coverage.yml` reports both trees with database integrations enabled; no
  percentage threshold is treated as proof of quality. To inspect locally, run
  `npm run test:coverage -- --coverage.reporter=text-summary --coverage.reporter=json-summary`
  in either tree.
- Dependabot's `Dependabot dependency inventory patch` run uploads `dependency-inventory-patch`. Review
  and apply it to the update branch, or regenerate with
  `node uploader/scripts/generate-third-party-inventory.mjs`. Review unknown licenses/evidence;
  do not regenerate inside the normal freshness test to make stale checked-in data pass.

## Runtime and test-count decisions

Baseline CI run 43466722672 recorded site 938 tests/24.32 s and uploader 5938 tests/309.93 s.
The editor DOM file alone took 68.54 s. It now caches compiled script objects while retaining
fresh documents, VM contexts, storage and fetch fixtures per case. It does not share mutable
application state, shorten settling deadlines or suppress race/failure cases. Compare future
CI on comparable runners before assigning a percentage speedup.
The focused local run after this change passed all 384 editor cases in 20.10 s; that is not
a controlled comparison with the hosted baseline. Backup schema introspection is also scoped
to `current_schema()` so another isolated fixture cannot duplicate its expected columns.

Onboarding/database and native architecture suites remain: their state transitions and ABI
boundaries are not duplicate coverage merely because counts are large. Shared-database files
stay serialized. PR cancellation removes obsolete runs; coverage stays off the PR critical
path. Decorative radius/class checks and script-include/redirect-spelling checks were removed
where behavior or real browser coverage now proves the user-facing contract. The two retired
issue-specific GitHub workflow registrations were disabled without deleting their history.
